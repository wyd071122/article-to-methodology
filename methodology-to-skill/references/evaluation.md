# 测试与修订

读取时机：生成 skill 后，需要验证它是否可用，以及变更后的回归检查。

## 两层检查

**蒸馏质量**：来源可定位，条件/公式/证据强度被保留，未读范围和新增设计明确；可以正确返回“没有合格方法”。

**使用质量**：生成的 skill 在新输入上实际完成任务，输出正确，缺输入时不猜值，边界条件下会停下或收窄结论。

只测是否触发不够。来源核验、触发/路由、实际使用和结构验证分别报告，不能用一个百分比遮盖关键失败。

## 先固定任务与检查项

每个有用的可执行单元至少有代表任务和一个缺输入或边界场景。多入口增加“应由同组另一个入口处理”的近邻请求；验证触发时，还要给执行者一个普通摘要请求，检查是否误生成 skill。

用表记录即可，不需要专门测试脚本：

| 用例 | 输入/请求 | 预先定义的可观察检查项 | 实际产物 | 结果 |
|---|---|---|---|---|
| 正常任务 | 新情境和完整参数 | 关键动作、分支、结果与单位 | 回答或文件路径 | 通过/失败/未运行 |
| 缺输入 | 少一个决定性参数 | 点明缺口，不猜数值，不下确定结论 | 回答或文件路径 | 状态 |

数值任务在运行前独立算出参考值，并检查比较运算、单位、取整和输出边界。流程任务核对行为和交付物，不按固定措辞判卷。

检查测试输入是否明确满足来源的适用前提，不能只补齐数值参数。用例遗漏前提、执行者因此合理补问时，该轮无法验证原定的计算边界；保留原输入和回答，记录“测试输入不足”，另建前提完整的用例重跑，不把原结果偷偷改成通过。只有预期或检查项本身有独立错误时才修订它们。

正常完成与正确停止配对测试：一致来源范围可以完成、有冲突范围只停相关动作；有流量可以计算、零分母保持未定义。具体边界以来源为准，不要求每种方法套上同一组极端输入。研究材料再补一个任务匹配检查，区分它所支持的测量与所不支持的干预。

## 实际执行

在宿主支持且当前任务允许独立评估时，按宿主的技能创建流程使用干净上下文测试：执行者仅获得待测 skill、任务和必要输入，不提供预期答案、失败诊断或评分表。把输出保存在隔离目录，不让测试触发发布、外部联系或真实业务写操作。

无隔离执行条件时，可在当前上下文实际跑任务，但标注为“同上下文自测”；它不能证明独立调用或默认发现有效。只有显式加载过 skill 时，不宣称自动触发已验证。

对生成的 skill 做使用测试时，执行者应只拿到该技能包和新任务，不依赖生成过程的源报告或隐藏知识。必要时复制到临时目录，检查能否仅靠相对引用工作。

## 记录与修订

保存任务输入、实际回答/文件、判断依据及测试环境。报告计划数、完成数、通过/失败/未运行数；每个关键错误单独列出。初次创建无旧版时，不必做旧版对照。

失败定位：

- 原文支持不了所声称动作 → 缩小范围或降级候选。
- 条件、分支、单位或缺输入处理不完整 → 修改执行契约。
- 描述误吸引摘要或近邻任务 → 修改触发边界。
- 测试预期超出原文或请求 → 记录独立理由后修改测试，不能为了通过而改答案。

修改后重跑受影响用例和关键回归；保留修改前结果。新保留用例用于减少只对已知输入适配的风险。没有真实比较数据，不声称优于某项目或提升某个百分比。

## 格式验证

运行宿主实际提供的官方 `quick_validate.py`，不要把一台机器上的绝对工具路径写进可开源技能指令。该验证主要覆盖 frontmatter 和命名，还需检查：

- `agents/openai.yaml` 可解析且任务名一致，default_prompt 含字面量 `$skill-name`。
- 参考文件存在、按需可达、没有越过技能包依赖项目外文件。
- 没有脚手架占位符、无用途的脚本、未声明的强制依赖。

Windows 下工具若使用默认本地编码读取 UTF-8 文本，可在该次运行启用 Python UTF-8 模式；区分环境编码错误与 skill 内容错误。工具不存在或无法运行时，记录原因和未验证范围，不能伪造成功。
