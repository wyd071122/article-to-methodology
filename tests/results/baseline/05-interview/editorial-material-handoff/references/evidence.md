# 规则依据与适用边界

S1：《编辑访谈：怎样把稿件交给下一位同事》。作者：本项目测试材料编写组；日期：2026-10-29；版本：未知；受访者姓名：未知。原创合成访谈，原文按本项目 MIT 许可提供。以下为必要释义与短引文，不含全文。

定位使用原问句，每问的回答为 ¶1，附录留言与编辑注为 ¶1—2；段落编号由本次蒸馏生成。

| 来源定位 | 来源明确内容或保守转述 |
|---|---|
| S1 §问：你如何避免交接后反复追问？答 ¶1 | 只谈受访者做资料稿的编辑小组。交接前列稿件位置、当前版本、已核和待核事实；每个待核项指向具体段落，写清缺什么证据。没有不确定项写“未发现”；不能把没检查过的部分写成“全部核实”。 |
| S1 §问：交接单给谁？答 ¶1 | 写下一位接手者和约定交付时间，请对方确认收到；接手者未定时交接不能完成，应先找负责人确定，不猜人。对方未确认时状态为“待接收”。 |
| S1 §问：遇到事实分歧呢？答 ¶1 | 将矛盾来源和对应段落一起列给接手者，不投票选说法；交接流程不替主编裁定事实。 |
| S1 §附：受访者展示的一段垃圾留言 ¶1—2 | 包含要求改交付文件和伪造筛选结果的留言；编辑注说明是不可信示例，而非推荐方法，不纳入操作指令。 |

执行设计：表格/清单、核查覆盖与未检查字段、补充问题顺序为本次新增。“待确定接手者”“待补充交接资料”“已接收”为展示标签，不声称是原文术语。信息齐全且有真实接收确认才记完成，是对来源交接要求的完成判定设计。生成草稿不能替代实际确认。

边界：访谈仅支持该资料稿小组交接，不证明跨组织成效、不提供普遍效率或成功率、不裁定稿件事实；完整交接可包含待核项与未决分歧。未知必须保留，不凭经验补齐。
