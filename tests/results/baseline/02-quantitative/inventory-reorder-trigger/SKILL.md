# 库存补货触发判断

用中文完成输入核实、单位统一、两个量的计算及比较。首次使用、单位或适用性有疑问时读取 [公式与来源边界](references/evidence.md)。来源为合成技术文章，不是已验证的库存政策；只能输出触发判断。

## 输入与适用范围

取得并保留输入原值及单位：

| 输入 | 含义 | 计算使用的单位/限制 |
|---|---|---|
| `d` | 稳定的平均需求率 | 件/天，非负 |
| `L` | 确定的交货提前期 | 天，非负 |
| `S` | 由计划人员提供的安全库存 | 件，非负 |
| `on_hand` | 现有库存 | 件 |
| `on_order` | 在途/已订购库存 | 件 |
| `allocated` | 已分配库存 | 件 |

确认需求稳定、交期确定。若交期可变或需求快速变化，停止使用本模型做确定补货判断，说明超出范围并请求合适的政策。用户没有说明这些前提时先核实，不能把假设写成事实。

任一必要值或单位缺失时列出已有数据与具体缺口，只问影响运算或适用性的缺项，不把未知当作零。来源没有选择安全库存的方法：缺 `S` 时请计划人员提供，不估计、不反推。`d`、`L`、`S` 为负时指出不合该规则，要求更正；为零可用。不能仅因最终 `P` 为负就判输入无效。

## 统一单位

把需求率与交期统一为“件/天”与“天”，库存量统一为同一种“件”。仅在转换关系由用户说明或没有歧义时换算，并展示依据及换算值；例如一周明确为七天可换算，而不明确的“月”不能默认为三十天。缺时间单位、换算关系不明或数量单位无法对应时先澄清，不据猜测计算。

## 计算与判断

在输入完整且适用条件成立后，按顺序计算并保留精度，不擅自取整或添加阈值：

1. 补货点 `R = d × L + S`，单位为件。展示代入的数值与单位。
2. 库存头寸 `P = on_hand + on_order − allocated`，单位为件。展示三个分量的代入式。
3. 比较 `P ≤ R`：成立就“触发补货”；不成立（`P > R`）就“未触发补货”。等于补货点时也触发。
4. 若 `P < 0`，另说明“负库存头寸表示短缺”，照常进行比较，不因负值拒绝该计算。

这个模型不提供订货量、供应商选择、持有成本或服务水平保证。用户同时索要这些结果时先完成本规则支持的部分，明确缺少对应政策；不要把 `R − P`、`R` 或 `S` 擅自写成订货数量。

## 输出与完成标准

交付输入与单位表、适用前提核实情况、必要的换算依据、`R` 的数值和代入式、`P` 的数值和代入式，以及带两个数值和单位的比较与触发结论。负 `P` 时附短缺说明。

不能计算或模型不适用时交付已知字段、缺失/无效项或超范围原因以及下一步请求，停止给出确定触发结论。完成标准是可复算的公式与单位、正确的 `≤` 边界、未伪造输入及未扩展为订货量。

表格、缺口记录和输出顺序是本次蒸馏添加的执行设计；公式、比较符号、参数限制和范围来自 [方法依据](references/evidence.md) 的 S1。
