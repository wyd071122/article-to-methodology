# 公式与来源边界

读取时机：首次使用、核查公式/单位/负库存头寸，以及判断模型范围或缺失参数时。此文件随技能包携带，不依赖原项目文件。

## 来源元信息

S1：*A reorder trigger for a small parts store*。Author: Project test-fixture authors。Date: 2026-10-29。额外版本号未知。原文声明为本项目原创合成技术文章，按本项目 MIT 许可提供，且不是已验证的库存政策。以下为中文释义和必要公式；没有附整篇英文文章。

原文标题、元信息及 Definitions、Compute the trigger、Scope 三节全部读取。定位沿用英文节标题；Compute the trigger 有两个段落，其余各一个段落。

| 来源定位 | 支持的规则与限定 |
|---|---|
| S1 Definitions ¶1 | 假设稳定平均需求率 `d`，单位 units/day；确定交期 `L`，单位 days；计划人员提供安全库存 `S`，单位 units。`d`、`L`、`S` 非负。文章不提供选取 `S` 的方法。 |
| S1 Compute the trigger ¶1 | `R = d × L + S`，单位 units。时间单位不同时，只有转换关系已说明或无歧义才可换算；缺时间单位必须澄清。 |
| S1 Compute the trigger ¶2 | `P = on_hand + on_order − allocated`，各量单位 units。`P ≤ R` 触发补货；`P` 负值表示短缺，不因其为负而无效。展示 `R`、`P` 及决定性的比较。 |
| S1 Scope ¶1 | 仅为触发规则，无订货量、供应商、持有成本或服务水平保证。交期可变或需求快速变化超出模型范围，应请求合适政策，不能默默扩展。 |

## 中文术语与执行设计

“件”对应原文 units，使用时必须确认所有数量属于同一计量单位；`on_hand` 译为现有库存、`on_order` 为在途/已订购库存、`allocated` 为已分配库存。`P` 是库存头寸，不以现有库存单独替代。

输入表、缺口记录、先核实模型前提、展示代入式及保留精度的输出约定，是本次蒸馏的执行设计或保守转述。原文没有取整规则；不能凭空向上取整。原文只明确要求 `d`、`L`、`S` 非负，未新增对 `P` 的非负限制。关于明确七天的一周和不明确月份的说明是单位规则的合成例示，不是原文案例。

原文没有安全库存选取算法或订货量公式。不得把缺失的 `S` 填为零，也不得把 `R − P` 当作本来源给出的订货数量。模型前提不成立时，算术可以成立也不代表政策判断适用。
